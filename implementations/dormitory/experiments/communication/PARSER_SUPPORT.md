# Language Parser: поддержка и проверка

После интеграции в MVP общий код находится в `game/communication/`: каталог содержит 69 форм / 71 чтение, текущий unit-прогон — 406 проверок. Пути `experiments/communication/parser.gd` и `word_catalog.gd` оставлены как адаптеры совместимости. Числа первоначального прогона ниже относятся к версии до интеграции; актуальный отчёт — [game/communication/INTEGRATION_REPORT.md](../game/communication/INTEGRATION_REPORT.md).

Основание: [LANGUAGE_PARSER_SPEC.md](https://github.com/ExecBit/language-life-sim/blob/docs/design-01-mvp-and-level-01/docs/LANGUAGE_PARSER_SPEC.md), ветка `docs/design-01-mvp-and-level-01`, прочитана 2026-11-09.

## Устройство

- `word_catalog.gd`: единый каталог для лексического анализа и автодополнения. 53 отображаемые формы, 55 лексических чтений. Каждая запись содержит `lemma_id`, `surface`, `pos`, `features`, `semantic_id`, `availability`. Неоднозначные `das` и `öffne` сохраняют оба чтения. Все формы доступны для ввода.
- `parser.gd`: Unicode-токенизация с позициями неизвестных токенов; лексические чтения; одна неглубокая конструкция; локальная область отрицания; семантический frame; сопоставление намерения. Разбор не читает состояние мира. Третий аргумент содержит только контекст разговора, необходимый для адресата и коротких ответов.
- `context.gd`: проверка статуса, контекста предложения и игровых предусловий; подготовленная реакция. Только `RECOGNIZED` допускается к разрешению действий. Исходный frame не изменяется. Уточнение, неизвестная и неподдерживаемая фразы не меняют владение, разрешение или дверь.
- `experiment.gd`: отображение результата, перенос единственного ключа, движение NPC, коллизия двери. Поля сохраняют режим редактирования после Enter, чтобы можно было составить несколько слов подряд.

`parse(text, pointed_target = "", conversation = {})` возвращает `status`, `intent`, `frame`, `ambiguity`, `unsupported_features`, `diagnostics`, `normalized_tokens`, `lexical_readings`. Статусы: `RECOGNIZED`, `NEEDS_CLARIFICATION`, `UNSUPPORTED`, `UNKNOWN`. Частичный frame сохраняется при отказе; числовой confidence не используется. Поля `target`, `subject`, `negative`, `modal`, `question`, `tokens` оставлены как совместимое представление, но не разрешают действия.

## Поддерживаемые семейства

| Конструкция | Результат / ограничения |
| --- | --- |
| `[ich] will/brauche OBJECT [bitte]` | `REQUEST_ITEM`, если субъект — игрок и адресат — Анна. Пропуск артикля/субъекта и ошибочное согласование диагностируются, но не блокируют однозначную просьбу. |
| `OBJECT bitte` | Телеграфная просьба, без вопросительного знака и отрицания. |
| `ich will OBJECT öffnen` | `EXPRESS_DESIRE`: игрок хочет действовать сам. NPC ничего не открывает и разрешение автоматически не выдаёт. |
| `ich will nicht öffnen`, `ich will OBJECT nicht` | Отрицательное желание; без положительного действия. |
| `Kannst du OBJECT öffnen?`, `Öffne OBJECT bitte` | `REQUEST_ACTION` с исполнителем Анной; состояние мира проверяется отдельно. |
| `Öffne OBJECT nicht` | `PROHIBIT_ACTION`, без открытия. |
| `ich habe keinen OBJECT` | `REPORT_PROBLEM`, предложение помощи без автоматической передачи. |
| `Anna hat keinen OBJECT` | `REPORT_STATE`, субъект Анна; это не проблема игрока и не обновление истинного местонахождения ключа. |
| `ich kann OBJECT nicht öffnen` | `REPORT_PROBLEM` о невозможности игрока открыть; без открытия. |
| `Wo [ist] OBJECT?`, `Warum ist OBJECT zu?` | Информационные намерения. Знания NPC проверяются отдельно. |
| `Was ist das?` + указание | Идентификация выбранного предмета. Без цели — уточнение. |
| `Kannst du mir helfen?`, `Hilf mir bitte`, `Helfen bitte` | `REQUEST_HELP`. Без цели — `Wobei?`, без автоматического открытия. |
| `Kann ich OBJECT öffnen?` | `ASK_PERMISSION`, без команды NPC открыть. |
| `Ja` / `Nein` | `ACCEPT` / `REFUSE` только при активном предложении помощи. Иначе уточнение; просроченный callback не принимает уже закрытое предложение. |
| `Tür` после `Wobei?` | Контекст уточняет объект исходной просьбы о помощи. Без такого контекста одиночный предмет не запускает действие. |
| `Schlüssel?`, `will`, `Das öffnen` | Уточнение; в последнем случае указанный предмет сохраняется во frame, но не превращает инфинитив в команду. |
| `Hallo`, `Hallo Anna`, `Danke` | Социальная реакция без предметного действия. |
| Обращение `Anna, ich ...` | Анна — адресат; явный субъект игрока сохраняется. |

Артикли, формы `kein/keinen/keine`, `will/willst/wollen`, `brauche/brauchst/brauchen`, `kann/kannst/können` берутся из каталога. Необходимые ошибочные сочетания допускаются с диагностикой `AGREEMENT_MISMATCH`, `OMITTED_ARTICLE`, `ARTICLE_MISMATCH`. Явный субъект, основной предикат, отрицание и вопрос не исправляются догадкой. Пунктуация, регистр и Unicode-пробелы нормализуются; модальная инверсия распознаётся без `?`.

## Контролируемые ограничения

- Придаточные с `dass`/`weil` и несколько клауз: `UNSUPPORTED`; знакомый императив не извлекается из неподдерживаемой структуры.
- Незнакомые слова, числа и символы: `UNKNOWN` с позицией токена. Неизвестный объект не наследует предыдущую или указанную цель.
- Неоднозначный scope, двойное отрицание, несколько предметов/предикатов и неполные конструкции: уточнение либо неподдерживаемая структура, без действия.
- Отрицательные модальные вопросы, вопросы об обладании, произвольные времена, согласование всех падежей и сложный порядок слов не поддерживаются.
- `hier`, `später`, `zu`, `wissen/weiß`, `öffnet`, `dass/weil` доступны лексически, но не являются самостоятельными командами. Отдельная форма возвращает контролируемое уточнение или `UNSUPPORTED_CONSTRUCTION`. Например, `zu` используется в вопросе о причине; `öffnet` позволяет корректно обнаружить известную, но неподдерживаемую придаточную конструкцию.
- Информационные утверждения и желания не переписывают истинные факты мира.
- Новый предмет добавляется записью каталога, но его реальные действия и визуализация требуют поддержки миром. `Zimmer` имеет отдельный semantic ID `room` и в этом эксперименте ссылается на существующую дверь `door`.
- Нет NLP-библиотеки, LLM, внешнего API или исправления произвольного немецкого.

## Автоматическая проверка

В PowerShell из папки проекта (подставить свой Godot, если имя отличается):

```powershell
$godot = (Get-Command Godot_v4.7.1-stable_win64_console.exe).Source
& $godot --headless --path . --script res://implementations/dormitory/experiments/communication/test.gd
& $godot --headless --path . --script res://implementations/dormitory/experiments/communication/test_input.gd
& $godot --headless --path . --script res://implementations/dormitory/experiments/communication/test_world.gd
& $godot --headless --path . --script res://implementations/dormitory/experiments/communication/test_regression.gd
& $godot --headless --path . --script res://implementations/dormitory/experiments/communication/test_pause.gd
```

Результаты разработки:

- `test.gd`: **358 проверок, 0 ошибок**. Таблица раздела 6 спецификации: статус, намерение, субъект, объект, полярность, речевой акт и отсутствие побочных эффектов. Метаморфные варианты артикля, вежливости, словоформы, субъекта, объекта и отрицания. Каталог/UI, позиции неизвестных токенов, указание, детерминизм и неизменность входного frame, владение/знания/занятость/разрешение, уточнения и повторные callback.
- `test_input.gd`: события `InputEventKey` проходят через viewport и сфокусированные поля. Префиксы `ich`, `will`, `sch` + Enter собирают `ich will Schlüssel`; следующий Enter передаёт один ключ. Enter в поле полного запрета не открывает дверь. Это проверка маршрутизации Godot, а не OS-раскладки.
- `test_world.gd`: реальная сцена, коллизия двери, та же модель ключа, передача и повторная просьба, самостоятельное открытие, помощь с уточнением, явная просьба NPC открыть с ходьбой, неизвестное местонахождение, отрицательные/неизвестные фразы.
- `test_pause.gd`: пауза, сохранение черновика/контекста, остановка NPC и сброс.
- `test_regression.gd`: отдельный прогон раздела 9 — R01–R15 и W01–W07, 27 вариантов. Отдельно сохраняются разбор, ответ NPC, мир до реплики, сразу после ответа и после завершения предметного действия. Коллизия проверяется фактическим перемещением; перед независимыми случаями выполняется сброс. Полный протокол и регрессия уровней 01–02: [REGRESSION_REPORT.md](REGRESSION_REPORT.md).

Успех тестов отмечается строками `COMMUNICATION_*_PASS`. В Godot при завершении остаются предупреждения ObjectDB/resource cleanup; headless также сообщает об отсутствии rendering device для DynamicInputIcon. Эти сообщения не считаются доказательством чистого завершения всего проекта.

## Ручная приёмка в Godot

Открыть `COMMUNICATION_EXPERIMENT.tscn`, F6, подойти к Анне или нажать T рядом с ней. Для немецкого ввода выбрать подходящую раскладку.

1. Набирать префиксы `ich`, `will`, `sch`, после каждого Enter; проверить, что получено `ich will Schlüssel`. При пустом префиксе ещё Enter: Анна отдаёт ключ. Закрыть ввод, дверь → E: проход свободен.
2. F5. `Kannst du die Tür öffnen?`: Анна идёт и открывает; ключ остаётся у неё. Повтор не создаёт новый ключ и не повторяет результат.
3. F5. `Helfen bitte` → уточнение; `Tür` → помощь. Отдельно `Ich habe keinen Schlüssel` → предложение; проверить `Nein` и после нового предложения `Ja`.
4. Сброс «Ключ на столе»: `Wo ist der Schlüssel?` → информация; `Ich will Schlüssel` не создаёт ключ у Анны. «Анна не знает» → нет выдуманного указания. «Анна занята» → отказ помочь сейчас.
5. После сброса проверить `Ich will die Tür öffnen`, `Ich will nicht öffnen`, `Öffne die Tür nicht`, `Anna hat keinen Schlüssel`, сложную клаузу с `dass` и неизвестный объект: нет передачи или открытия.
6. `Schlüssel?`, `Das öffnen` с указанием и без: уточнение; полноценная последующая просьба остаётся доступна. Проверить FPS, отмену, паузу и повторный запуск.

**Ручная приёмка не завершена.** Графическая сцена запускалась; попытка OS-ввода через computer-use столкнулась с русской раскладкой и отсутствием Unicode-ввода в Godot. Полные маршруты обоих решений человеком в текущей версии не подтверждены. Автоматические проверки viewport/мира это ограничение не заменяют.
